# 解压安全

文件名按不可信 UTF-8 路径处理。提取拒绝绝对路径、父目录跳转、盘符、反斜杠、符号链接、硬链接和特殊条目。允许 TAR 路径使用常见的 `./` 前缀。Core 从打开的目标目录描述符开始，通过 `openat`、`mkdirat` 和 `O_NOFOLLOW` 逐级访问目录。现有符号链接和非预期文件类型会被拒绝。提取只创建普通文件和目录，归档权限、所有者、ACL 和扩展属性不会应用到目标目录。

默认限制为每文件 4 GiB、实际解码合计 16 GiB、10,000 个条目、32 级路径、全归档 1000:1 展开比。已知尺寸在写入前检查，流输出在每个读取块后再次检查。已知 TAR 外层压缩只打开一层。Core 在归档读、块处理和提交时检查取消。固实压缩或顺序容器可能需要读取被跳过的条目，相关解码量计入预算。

普通文件先写到同目录的独占临时文件。数据完整读取后原子发布。冲突策略支持停止、跳过或替换普通文件。取消和常规错误会清理正在写入的临时文件，先前已发布的文件及已创建目录会保留。对于使用硬链接发布的文件系统，目标存储需要支持该操作。目标目录应由调用者控制，不与不受信任的本地进程并发重命名或修改。进程被强制终止时，同目录临时文件可能残留。

ZIP 密码只用于当前 Swift 任务。App 在安全输入框提交后清空输入，最近记录和任务历史不保存密码。SDK 在写入前尝试读取所选加密条目的开头，以便在原目录重试常见密码错误。文件提交仍以完整条目读取和驱动校验为准。

文件内容预览在私有临时目录中暂存单个普通文件，使用生成的文件名和允许的类型后缀。除用户配置的解压限制外，预览最多暂存 32 MiB。读完条目并通过驱动校验后才显示内容。关闭预览、取消或读失败会清理暂存文件。进程被强制终止时，暂存文件可能残留在 App 临时目录内。

输出预算约束读取到调用方的解码量。解析容器索引和编解码器内部工作集仍由固定版本的 libarchive 和解码依赖控制。进度以条目为单位，已知大小的文件显示块级进度。

GZIP 解码器读取到每个成员的尾部时会校验 CRC-32 和 ISIZE。独立 `.gz` 提取会读完整个流，验证失败时清理暂存文件。提前结束的读取、选定 TAR 条目提取以及已经发布的文件仍遵循逐文件提交规则。

嵌套挂载由调用方显式发起。Core 使用现有解码上限，并检查祖先链的嵌套层数及暂存字节数。嵌套归档完整读取后才进入下一层识别。调用方提供自己控制的暂存目录，文件在写入之前解除目录链接，随最后一个读取句柄关闭而释放。
